## About

A structured collection of my **Data Structures & Algorithms** practice,
focused on building problem-solving intuition rather than memorizing solutions.
Problems are organized around **patterns and techniques** so that the goal
is not only to solve a problem, but to recognize *why* a particular approach
works and when to apply it in a new problem.

---

## Repository Structure

```text
<pattern>/
└── <problem-name>/
    └── solution.cpp
```

Problems are grouped by **problem-solving pattern** rather than platform
problem number, making the repository easier to navigate and revise.

## Problem-Solving Philosophy

For each problem, the focus is on:

**Understand → Identify the Pattern → Build the Approach → Optimize → Implement**

Solutions aim to capture:

* The underlying problem-solving pattern
* Why the approach works
* Time and space complexity
* Common edge cases
* The transition from brute force to an optimized solution
